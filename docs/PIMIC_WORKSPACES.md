# PiMic：目标切换、独立草稿与常驻 Pi 操作

版本 `1.2.0+12`。这是一项独立可选功能，首次安装及旧配置升级后均默认关闭。
不要求 STT、优化 API 或额外服务器，不改变原版配对和消息发送路径。

## 开启和使用

Settings → **PiMic · Voice & draft tools** → 开启
**目标切换与草稿缓存（可选）** → **Save settings**。

进入一个已配对会话后，顶部增加两个按钮：

- **↔ 切换机器 / 项目 / 会话**：展示既有配对机器及已发现/缓存的房间，
  按机器和项目目录分组。支持搜索名称/目录、星标和“仅收藏”筛选。
  连接状态来自原版 Relay；Relay 断线显示“连接状态未知”。
- **/**：打开原版 Quick Actions，可选模型、思考级别、新会话及压缩。
  输入文字后仍显示；目标离线、连接未就绪或 Pi 运行中会禁用并提供原因。
  各动作仍由原版 typed action 处理；没有新增任意斜杠命令执行。

每台 Pi 首次仍须独立配对。STT/优化接口与聊天目标无关，切换 Pi 不要求
重新配置识别服务。列表不扫描文件系统，也不根据展示名称猜测目标。

## 草稿和阅读位置

目标用稳定 **peer identity + room ID** 区分，相同名称、相同目录或不同机器
同名房间不会共用草稿。A → B → A 恢复各自未发送文字和滚动偏移；切换
不会发送消息、停止其他 Pi 任务或把草稿搬到新目标。正常发送清空当前草稿。

缓存仅保存在本次 app 进程内存：

| 内容 | 边界 |
| --- | --- |
| 文字/滚动缓存 | 最多 32 个目标，按最近使用淘汰 |
| 单个文字草稿 | 64,000 字符 |
| 所有文字 | 512,000 字符 |
| 收藏 | 最多 128 个目标，本次运行有效 |

关闭功能、身份重置或 app 进程退出后清空，不写入文件/云端。超长文字仍在
当前输入框，目标按钮会要求先复制或缩短；不会截断文本。离开聊天、原版
导航或系统回收进程不保证超长草稿保留。滚动位置是像素偏移，消息数量变化
时不是精确消息锚点。

录音、原版转写或待发送/正在选择附件期间，目标按钮会要求先完成或移除。
常驻 Pi 操作入口也会检查相同条件，避免在录音/附件流程中开启新会话。
可选语音草稿弹窗沿用此前的目标/设置变化取消机制。关闭功能、身份重置
或外部改变当前目标，会取消已打开的目标列表，避免迟到的选择覆盖新目标。

## 兼容和实现边界

- UI、缓存、搜索位于 `app/packages/pimic_addons/`；宿主选择/路由适配器
  位于 `app/lib/pimic_bridge/workspace_widgets.dart`。
- 宿主只增加输入草稿和滚动 controller 接口、固定目标路由参数及按钮。
  复用 `HomeViewModel.openSession`、`SessionSelection` 和原版快捷操作。
  未改 Relay、Pi extension、ChatViewModel、原版录音服务和 Send 处理器。
- `main` 保留上游基线；改动在 `pimic/voice-addon`。PR #1 仍为 Draft，
  安装构建来自该分支不代表 PR 已合并。
- 历史 JSONL 会话恢复、扩展命令目录/结果协议、任意 TUI 表单尚未实现。
  已缓存房间列表与磁盘上历史会话列表是不同能力。

2026-10-04 查询的上游 [#223](https://github.com/jacobaraujo7/remote_pi/issues/223)、
[#194](https://github.com/jacobaraujo7/remote_pi/issues/194)、
[#176](https://github.com/jacobaraujo7/remote_pi/issues/176) 仍开放；它们是 Issue，
不能当作已合并 PR。这个版本仅在 addon 边界实现目标切换与常驻原版操作。

## 本轮验证

696 项 Dart 测试通过：应用 572、addon 107、原身份包 17。包含真实路由
A → B → A、草稿隔离/清空、目标竞争、身份重置取消、默认关闭回归、
搜索/收藏、缓存边界和滚动恢复。测试使用离线假 transport，不执行 Pi
模型请求。静态检查无问题，ARM64 debug APK 构建成功。

Wi-Fi ADB 在真实手机升级版本 12，保留本地身份、Relay、配对、mac7 STT
及关闭的优化设置。已明确开启目标工具，进入缓存的离线测试房间并查看
分组列表、当前目标、项目路径与离线状态；未执行 Pi 操作或发送消息。
多台真实在线 Pi 的完整切换尚未验收，A → B → A 路由由离线 widget 测试覆盖。

mac5 的 SSH 域名为用户指定的 `mac5.pi.jmsu.top`。首次确认时其公钥与
Windows 已信任的该机器 IP 记录一致，按用户确认添加域名记录；没有替换
已有主机公钥或关闭校验。桌面 oMLX 为 0.7.0、64 GB 内存，健康检查和
模型目录接口正常。当前监听 `127.0.0.1:18082`，手机不能直接访问此地址。
本轮通过 SSH 在 Mac 本机探测，手机优化功能继续关闭。未更改 oMLX 全局
认证、端口、监听地址、模型驻留或安装方式。

通过 SSH 在 Mac 本机对 `Qwen3.8-27B-oQ4e-fp16-mtp` 做了三条人工测试稿、
两种模式的探测。使用 app 同一套规则，额外按请求设
`chat_template_kwargs.enable_thinking=false`，没有修改全局模型配置。
最终一轮“仅纠错”中位 1.313 秒（0.868–1.669），“整理提示词”中位
4.963 秒（4.177–5.430）。之前首次加载耗时 64.506 秒，服务报告模型加载
60.22 秒；实际手机体验需另计网络、说话和请求处理。

第一次整理曾把中文改成英文并补写输出要求，因此加强了原语言、时间、
范围/否定原句和不补写的规则。最终三条结果保留了测试中的路径、数字、
“今天”“只报告问题”“不要执行命令/删除文件”。整理仍可能改变对象关系
或省略细节，三条不是准确率基准，不代表语义完全等价。默认继续仅纠错、
优化需明确选择并对照采用；本轮未测试手机到 mac5，也没有新录音准确率。
